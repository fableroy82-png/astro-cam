Acquisition / INDI

- INDI démarre automatiquement avec Astro Cam.
- Détection dynamique de la caméra :

- Arrêt propre de la caméra et du serveur INDI.
- Récupération caméra déjà présente :
  - réarmement BLOB ;
  - reconnexion INDI ;
  - sans relancer systématiquement indiserver.

Plate solving

- Temps de solve typique :

Push-To

Focus plein jour
----------------
- Script séparé créé :
  focus_plein_jour_sc715c_v2.py
- Démarre INDI automatiquement.
- Flask sur le port 5051.
- Gain + exposition uniquement.
- Dématriçage Bayer GRBG.
- Aucun stretch astro.
- Aucun gamma.
- Aucun histogramme automatique.
- Aucun plate solving.
- Sert surtout à :
  - régler mécaniquement la caméra ;
  - vérifier l'orientation ;
  - faire une mise au point grossière en journée.
- En plein jour, même au minimum, la caméra est très lumineuse.
- Solution mécanique envisagée :
  diaphragmes imprimés en 3D, environ 8 / 10 / 12 / 15 / 20 mm.
- Point de départ conseillé pour le plein jour :
  trou autour de 10 mm.

2. PRIORITÉ 1 — VALIDER LA V35 / V36 SOUS LES ÉTOILES
======================================================================

Objectif :
valider définitivement les nouveaux sens de déplacement après rotation
physique de la caméra.

À tester avec une cible connue :
1. Lancer un solve.
2. Choisir un objet.
3. Vérifier :
   - si l'écran dit DROITE, tourner réellement à droite ;
   - la distance à la cible doit diminuer ;
   - si l'écran dit GAUCHE, tourner à gauche ;
   - si l'écran dit MONTE, monter ;
   - si l'écran dit DESCENDS, descendre.
4. Vérifier que la flèche jaune globale pointe dans la bonne direction.
5. Vérifier que la distance diminue de façon cohérente à chaque mouvement.
6. Refaire le test avec plusieurs objets éloignés les uns des autres.

IMPORTANT :
ne plus corriger les directions par hypothèse.
Toute correction future doit être basée sur un test physique réel.

3. PRIORITÉ 2 — ÉVITER LES PLATE SOLVING SUR IMAGE EN MOUVEMENT
======================================================================

Problème observé :
- pendant un déplacement manuel, une image peut être acquise avec les
  étoiles étirées ;
- l'auto-solve peut démarrer sur cette image ;
- le solve échoue ou donne un mauvais résultat ;
- on peut perdre un ou deux cycles de solve avant stabilisation.

Amélioration à développer :
détection de stabilité avant auto-solve.

Comportement souhaité :
1. Le télescope bouge.
2. Astro Cam détecte que l'image n'est pas stable.
3. Aucun plate solving n'est lancé.
4. Message possible :
   "Mouvement détecté — attente stabilité..."
5. Une fois le télescope arrêté :
   - attendre 2 images consécutives stables ;
   - utiliser seulement la plus récente ;
   - lancer le solve.
6. Message :
   "Image stable — plate solving..."

Méthodes possibles :
- comparaison entre deux images successives ;
- déplacement global des étoiles ;
- mesure de netteté / allongement ;
- détection rapide avant solve, sans traitement lourd.

But :
perdre 2 ou 3 secondes à attendre la stabilité plutôt que perdre
8 à 16 secondes avec un ou deux solves inutiles.

12. PRIORITÉ 11 — CARTE / MEZZANINE / ÉLECTRONIQUE
======================================================================

Brochage actuellement prévu :
- D3 / PB0  : ST4 RA+
- D4 / PA12 : ST4 RA-
- D5 / PA11 : ST4 DEC+
- D6 / PB1  : ST4 DEC-
- D7 / PB2  : switch réseau / hotspot
- D8 / PB4  : LED verte test carte
- D9 / PB8  : Canon Focus
- D10 / PB9 : Canon Shutter
- VIN        : 12 V
- GND        : masse logique / alimentation

PC817C :
- pin 1 = anode
- pin 2 = cathode
- pin 3 = émetteur
- pin 4 = collecteur

Entrée :
GPIO -> 220 ohms -> pin 1
pin 2 -> GND Arduino

Côté isolé :
pin 4 -> signal externe
pin 3 -> commun externe

À finaliser :

- fusible ;
