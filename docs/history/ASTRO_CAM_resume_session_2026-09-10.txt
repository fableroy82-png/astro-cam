ASTRO CAM — RÉSUMÉ DE LA SESSION
Date : 10 septembre 2026

============================================================
1. OBJECTIF GÉNÉRAL DU PROJET
============================================================

Le projet Astro Cam doit utiliser la caméra SVBONY SC715C montée sur un chercheur 9x50 d’environ 184 mm de focale, pilotée par l’Arduino UNO Q.

Fonctions prévues à terme :
- affichage vidéo / preview Web ;
- réglage exposition et gain ;
- focus assisté ;
- détection d’étoiles ;
- HFD / FWHM ;
- plate solving ;
- mise en station polaire ;
- push-to ;
- guidage ST-4 ;
- interface Web utilisable depuis PC ou téléphone.

Architecture retenue :
- driver caméra séparé via INDI ;
- application Astro Cam séparée ;
- acquisition, traitement, JPEG et serveur Web dans des processus distincts ;
- communication entre processus par mémoire partagée ;
- principe “latest frame wins” ;
- aucune queue d’images qui grossit ;
- aucune écriture FITS sur disque pendant le live.


============================================================
2. PROBLÈME INITIAL ET DIAGNOSTIC
============================================================

L’ancien système utilisait un démon caméra écrit en C, basé directement sur les bibliothèques caméra.

Symptômes observés auparavant :
- plantages aléatoires ;
- instabilité après quelques minutes ou parfois beaucoup plus tard ;
- problèmes de buffers ;
- comportement difficile à diagnostiquer ;
- nombreuses tentatives autour du streaming et de l’acquisition.

Conclusion actuelle :
- le démon C précédent était très probablement incomplet ou mal configuré pour cette caméra ;
- il manquait vraisemblablement certains paramètres / comportements de gestion attendus par la caméra ;
- le passage par INDI s’est révélé nettement plus stable.

============================================================
4. VALIDATION DES FITS ET DU RAW
============================================================

Un FITS de test a été généré et vérifié.

Résultat :
- 1920 x 1080 ;
- BITPIX = 16 ;
- exposition correcte ;
- gain correct ;
- matrice Bayer GRBG ;
- sortie réellement produite en binning 2x2.

Les valeurs observées étaient des multiples de 16, ce qui confirme que les données utiles 12 bits sont alignées dans le conteneur 16 bits.

Conversion retenue :
    raw12 = raw16 >> 4

============================================================
6. CONVERSION BAYER -> NIVEAUX DE GRIS
============================================================

Au début, la preview présentait un damier très visible.

Diagnostic :
- le RAW Bayer GRBG était étiré directement ;
- les composantes R/G/B étaient très différentes.

Exemple observé :
    CFA(GR/R/B/GB) ≈ 417 / 223 / 277 / 417

Correction :
- conversion Bayer GRBG vers image monochrome avant l’histogramme / stretch.

Résultat :
- le damier Bayer a pratiquement disparu ;
- l’image restante est surtout du bruit amplifié, ce qui est normal puisque la caméra filme actuellement des volets fermés et non le ciel.

============================================================
8. PROBLÈME DES CONNEXIONS INDI COURTES
============================================================

Un nouveau problème a été repéré pendant le développement :
indiserver affichait régulièrement :
- New arrival ;
- read EOF ;
- shutdown complete.

Cause :
- le endpoint Web /api/status ouvrait une petite connexion TCP vers INDI toutes les secondes pour tester si le port répondait.

Important :
- ce n’était pas l’acquisition des frames ;
- l’acquisition principale était déjà persistante.

Correction :
- suppression du socket de test périodique ;
- création d’un état partagé “INDI connecté” ;
- le process acquisition met cet état à jour ;
- /api/status lit seulement cette valeur ;
- plus de connexion INDI ouverte / fermée toutes les secondes.

Architecture actuelle :
- une vraie connexion INDI persistante pour l’acquisition ;
- pas de reconnexion à chaque frame ;
- pas de connexion périodique uniquement pour les voyants Web.

Le temps de cycle dépend donc bien de l’exposition demandée.

Les changements d’exposition et de gain depuis la page Web sont bien transmis jusqu’à la caméra.

Exemples de gains testés :
